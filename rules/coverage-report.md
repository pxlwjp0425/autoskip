- **8 个**是你的 App 里**原来完全没有专属规则**的（纯新增）

## 四、为什么覆盖率不是 100%

**表达力差距**，没有别的办法。上游 GKD 订阅 3217 条规则里，只有约 61% 能用
「文本 / 描述 / 资源ID」三选一表达；剩下的是纯结构定位：

```
RelativeLayout[childCount=2] > ImageView[id!=null] + ImageView[clickable=true]
```

快跳没有选择器链、没有兄弟/层级/索引关系，这类规则**转不了**，硬转会变成误点。
李跳跳那边也一样，它自己的 README 就因为「很多弹窗的控件没有任何可标识文本」而放弃了一批应用。

## 五、安全验证（本轮重点）

新加 796 条规则，最坏情况是**误点**。做了两层验证：

**1. 离线回放（`tools/ltt_verify.py`）**
拿快跳诊断模式抓下来的**真实节点树**（10 个应用的冷启动过程，共 71 帧有效界面），
按引擎同样的判定顺序重跑全部规则：

```
有效帧: 71  规则命中次数: 2  其中李跳跳式(带anchor): 0
```

命中 2 次都是朴朴超市真实的「跳过 3s」开屏按钮（正确命中，同一按钮被两条规则命中）。
**796 条李跳跳式规则在正常界面上零误触发。**

**2. 真机正例**
百度文库的通知权限弹窗被正确跳过（见上文日志），证明 `anchor` 前提机制在真机上工作。

## 六、已知问题

### 1. 全局规则会误点长文本

日志里有这类记录：

```
跳过 com.android.shell · 开屏广告-全局 · 「在哔哩哔哩国际版里自动跳过赞助/恰饭…」
跳过 com.android.settings · 开屏广告-全局 · 「快跳 · 自动跳过」
```

全局组的正则 `(?is).*skip.*` 会命中**任何**含 "skip" 的文本，包括长句和说明文字。
`com.android.shell` 那批是 `monkey` 测试命令带来的（日常使用遇不到），
但 `com.android.settings` 里点到「快跳 · 自动跳过」是真实的。
后果轻（点在文字上通常无操作），不过这是**既有问题**，不是本轮引入的。
要根治需要给全局正则加长度上限或降权。

### 2. 上游订阅都在停更

- GKD 侧：AIsouler、Adpro **均已停止维护**
- 李跳跳侧：仓库已声明**不再更新应用内广告 / 弹窗规则**

短期靠这份快照没问题，长期建议换到还在维护的源。
